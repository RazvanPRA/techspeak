# Milestone 3 plan: backend, Azure scoring, scenarios (days 11–18)

## Context
Whisper's STT-diff scoring is lenient (it auto-corrects toward plausible words), so real diction
feedback needs Azure Pronunciation Assessment. The "explain it like in an interview" practice
(SPEC.md §3.4) needs feedback on spoken answers. Azure needs a secret key, which must never be in the app, so this
milestone adds the `server/` backend (NestJS + Prisma + PostgreSQL), the scenarios feature and a
Postman collection.

Workflow: `techspeak-milestone` skill. Rules: `modular-architecture`, no Expo, no API keys in the
app, tests first for pure services, implementations chosen only in `app/src/app/dependencies.ts`.

## Cost constraint: free only
Everything in this milestone must run at $0. Azure Speech uses the **free F0 tier**.
The **Claude API is deferred** (paid): scenarios get feedback computed locally, and the
`FeedbackProvider` interface stays ready so Claude (or a local model) can be plugged in later
without touching callers. Publishing (Google Play / App Store) is out of scope.

## Prerequisites
- Milestone 2 done and committed.
- Docker Desktop, ffmpeg on PATH.
- Azure Speech resource on the **F0 (free) tier** (key + region), in `server/.env` only
  (`.env` git-ignored; `.env.example` committed with empty values).

## Steps

### 1. Scaffold `server/`
- NestJS (TS strict), Prisma, PostgreSQL in `server/docker-compose.yml`.
- Global `ValidationPipe` (whitelist, transform), `ApiKeyGuard` (header `x-api-key`),
  `@nestjs/throttler`, Swagger at `/docs`, `ConfigModule` with a zod-validated env schema
  (fail fast on a missing key).

### 2. Prisma schema
- `Attempt`, `ScenarioAnswer`, `Feedback` (JSON column holding the validated feedback). First migration.

### 3. assessment module
- `POST /assessment`: multipart audio + `referenceText`.
- `AudioConverter`: ffmpeg → 16 kHz mono WAV (skipped when the input already is).
- `AzurePronunciationClient` behind an interface: word and phoneme accuracy, fluency, prosody,
  completeness → response DTO.
- Unit tests with a fake client; one e2e test with supertest.

### 4. feedback module (free, rule-based)
- `POST /feedback`: prompt, deck, transcript, durationSeconds, optional pronunciation scores.
- `FeedbackProvider` interface + `RuleBasedFeedbackProvider` (default, $0):
  - fluency: words per minute, filler count and list, very long sentences;
  - pronunciation: words with Azure accuracy < 70, with a tip from a static tip table
    (θ/ð, w/v, ɪ/iː, word stress, silent letters, `-ed` endings);
  - vocabulary: which deck terms were used, and which key terms were missing;
  - `phrasesToReuse`: picked from the deck's example sentences in `VOCABULARY.md`.
- Same zod `FeedbackSchema` as PROMPTS.md Part B; fields that need an LLM
  (`corrections`, `improvedAnswer`) are returned empty.
- Store `ScenarioAnswer` + `Feedback`.
- **Later (not now):** `ClaudeFeedbackProvider` using the Part B prompt, or a local model via
  Ollama, swapped in by config only.

### 5. App side
- `src/services/api/`: small typed HTTP client + RTK Query slice. Base URL and app API key from
  build config (dev only), no Claude/Azure keys.
- `AzurePronunciationAssessor` implements the existing `PronunciationAssessor`
  (`services/speech/model/types.ts`). Chosen in `dependencies.ts`, falls back to `SttDiffAssessor`
  when the server is unreachable.
- **features/scenarios:** prompt list from `src/content/prompts.json` → pick → 60–120 s timer →
  record → Whisper transcript → `POST /feedback` → feedback screen: score, transcript,
  pronunciation tips, fluency (WPM, fillers), deck terms used/missing, 3 phrases to reuse.
  The "a better way to say it" section stays hidden while `corrections`/`improvedAnswer` are empty
  (they need an LLM, deferred).
- Pure services `countFillers` and `wordsPerMinute` (tests first).
- Add a Scenarios tab to `src/app/navigation/RootTabs.tsx`.

### 6. Postman
- `postman/TechSpeak.postman_collection.json` + `postman/local.postman_environment.json`
  (`baseUrl`, `apiKey`), example requests and basic tests for both endpoints.

## Reuse
- `PronunciationAssessor` interface + `SttDiffAssessor` as the fallback
- `RecorderRepository` / `RecognizerRepository` (Whisper) for recording and transcripts
- `diffWords` (`services/scoring`) for the "said vs better" diff
- `src/content/prompts.json` (already generated by `yarn build:seeds`)

## Verification
- `yarn --cwd server test` (unit + e2e) green; app `typecheck`, `lint`, `test` green.
- `docker compose up -d`, `yarn --cwd server start:dev`, open `http://localhost:3000/docs`.
- Run the Postman collection against local.
- Emulator (`adb reverse tcp:3000 tcp:3000`): answer one scenario end to end and see the feedback
  screen; a shadowing attempt shows Azure word scores; stop the server → shadowing still works (fallback).
- Update `docs/progress.md` and summarise per the skill.

## Out of scope
Claude API / any paid service, `sync` module, production deployment, publishing to stores,
mock interview (milestone 4).
